# 美菱 KKZM-4WB 红外协议记录

本文记录通过 ESP32-S3 和 Arduino-IRremote 4.7.1 实测得到的协议结构。
Arduino-IRremote 将其识别为通用 `PulseDistance`，暂无对应的内置品牌协议名。

## 基本参数

- 载波：38 kHz
- 数据长度：120 bit，共 15 字节
- 位序：LSB first
- 帧头：约 8450 µs mark + 4200 µs space
- 逻辑 0：约 550 µs mark + 550 µs space
- 逻辑 1：约 550 µs mark + 1600 µs space
- 帧尾：约 550 µs mark
- 单帧时长：约 157～162 ms

## 数据排列

Arduino-IRremote 输出两个 `uint64_t`。第一个数保存前 8 字节，第二个数保存
剩余 7 字节；每个字节按 LSB first 发送。

目前确认的 15 字节结构：

| 字节 | 用途 |
| --- | --- |
| 0 | 固定值 `0x56` |
| 1 | 整数温度：`温度 + 0x5C` |
| 2 | 当前通常为 `0x00` |
| 3 高半字节 | 温度小数位 0～9 |
| 3 低半字节 | 部分风速档位标志 |
| 4 | 模式与风速字段 |
| 5 | 关机、关屏等动作标志 |
| 6～13 | 多数普通状态下为零；部分功能使用 |
| 14 | 校验值 |

## 温度编码

完整采集范围为 16.0～32.0℃，步进 0.1℃。

```text
byte[1] = temperature_integer + 0x5C
byte[3] high nibble = temperature_decimal
```

边界与进位示例：

| 温度 | byte 1 | byte 3 高半字节 |
| --- | --- | --- |
| 16.0℃ | `0x6C` | `0x0` |
| 16.1℃ | `0x6C` | `0x1` |
| 16.9℃ | `0x6C` | `0x9` |
| 17.0℃ | `0x6D` | `0x0` |
| 24.0℃ | `0x74` | `0x0` |
| 24.5℃ | `0x74` | `0x5` |
| 25.0℃ | `0x75` | `0x0` |
| 32.0℃ | `0x7C` | `0x0` |

普通状态帧示例：

| 温度 | 第一段 | 第二段 |
| --- | --- | --- |
| 24.0℃ | `0x0000002200007456` | `0x001A000000000000` |
| 24.1℃ | `0x0000002210007456` | `0x001B000000000000` |
| 24.5℃ | `0x0000002250007456` | `0x001F000000000000` |
| 25.0℃ | `0x0000002200007556` | `0x001B000000000000` |

实体遥控器按温度键时还会出现瞬时动作标志：byte 3 低半字节为 `1`，byte 5
为 `0xC0`。空调也接受不含动作标志的普通状态帧，因此 HomeKit 使用普通帧。

## 校验算法

最后一个字节等于前 14 字节所有十六进制半字节之和，结果保留低 8 位。

例如 24.1℃普通制冷帧的非零半字节为：

```text
5 + 6 + 7 + 4 + 1 + 2 + 2 = 27 = 0x1B
```

## 电源控制

在制冷 25.0℃下的受控采集：

| 动作 | 第一段 | 第二段 |
| --- | --- | --- |
| 开机 | `0x0000002200007556` | `0x001B000000000000` |
| 关机 | `0x0000C02200007556` | `0x0027000000000000` |

- 开机发送当前模式、温度的普通状态帧。
- 关机在 byte 5 中加入 `0xC0`，并重新计算校验。
- 早期出现过含 `0x50` 的帧，但受控测试证明它不是可靠的关机编码，固件不再使用。

## 模式编码

实体遥控器有四种模式，没有独立自动模式：

| 模式 | 普通状态帧第一段 | 第二段/校验 |
| --- | --- | --- |
| 送风 | `0x0000005300007456` | `0x001E000000000000` |
| 制冷 | `0x0000002200007556` | `0x001B000000000000` |
| 除湿 | `0x0000003000007456` | `0x0019000000000000` |
| 制热 | `0x0000001000007456` | `0x0017000000000000` |

HomeKit 当前只暴露制冷和制热。模式切换使用普通状态帧，不使用早期采集到的
`0xC0` 瞬时动作形式。

## 风速编码

在制冷 25.0℃下确认六档循环：

| 档位 | 第一段 | 第二段/校验 |
| --- | --- | --- |
| 1档 | `0x0000002201007556` | `0x001C000000000000` |
| 2档 | `0x0000002200007556` | `0x001B000000000000` |
| 3档 | `0x0000002300007556` | `0x001C000000000000` |
| 4档 | `0x0000002100007556` | `0x001A000000000000` |
| 最强 | `0x0000002100007556` | `0x0022000000000080` |
| 自动 | `0x0000002000007556` | `0x0019000000000000` |

HomeKit 映射：`0%=自动`，`20%=1档`，`40%=2档`，`60%=3档`，
`80%=4档`，`100%=最强`。制热模式下的风速组合编码目前由制冷模式规律推导，
尚未逐档实测。

## 关屏/开屏

关屏和开屏使用同一个无状态切换命令。在制冷 25.0℃下：

```text
0x0000042200007556, 0x001F000000000000
```

切换标志为 byte 5 的 `0x04`。Apple Home 没有标准“空调显示屏”特征，固件
使用空调服务中的“摆风”开关承载该功能。若同时使用实体遥控器，Home App
无法获知实际显示屏状态，界面状态可能与空调不同步。

## 当前固件映射

- 固件版本：`2.0.9`
- HomeKit 模式：制冷、制热
- 温度：16.0～32.0℃，0.1℃步进
- 风速：自动及五档手动风速
- “摆风”：实际执行关屏/开屏
- “当前温度”：回显最后发送的设定温度，不代表真实室温
